# Installed artifacts

These are the files the integration set up in the `aws-cli` demo project, captured
verbatim so you can see exactly what ends up on disk after following the blueprint.

## Project-local — written by `sonar integrate antigravity`

Everything under `.agents/` is generated in your project root by the integrate
command (blueprint, Step 2):

- `.agents/hooks.json` — registers the `PreToolUse` secrets hook, matched to the `view_file` tool
- `.agents/sonar/hooks/pretool-secrets.sh` — the hook script; shells out to `sonar hook antigravity-pre-tool-use`
- `.agents/rules/sonar-agentic-analysis.md` — the Sonar Vortex verify rule (end-of-turn `sonar analyze agentic --depth DEEP`)
- `.agents/rules/sonar-prompt-secrets.md` — the prompt-secrets scanning rule
- `.agents/skills/sonar-context-augmentation/SKILL.md` — the Sonar Vortex guide (context and constraints) skill
- `.agents/instructions/sonarqube.instructions.md` — present but empty in this project (not documented in the blueprint's Step 2 list)

## Project config — created before integrating

- `sonar-project.properties` — points the project at SonarQube Cloud (organization, project key, sources, Python versions)

## Global — the MCP patch

- `mcp_config.global.json` — a copy of `~/.gemini/config/mcp_config.json`, the MCP
  server registration the integration patches in. This lives in your home directory,
  **not** the project. It's included here only for reference.

## Notes

- `sonar-project.properties` and the `sonar-agentic-analysis.md` example commands
  contain this demo's real organization and project keys
  (`taylor-luttrell-williams-sonarsource` / `taylor-luttrell-williams-sonarsource_aws-cli2`).
  Swap them for your own before reusing, and redact if you'd rather not publish them.
- The `.agents/` files are generated by the SonarQube CLI at integration time and
  reflect CLI/plugin versions current when this project was set up. Re-run
  `sonar integrate antigravity` to regenerate them.
